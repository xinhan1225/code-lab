# 课堂汇报建议（约 6—8 分钟）

## 开场：为什么做这个游戏（1 分钟）

初学者往往能记住 for、if，却难以把代码和运行结果联系起来。本项目把代码变成机器人的动作：顺序改变路线，循环改变步数，条件判断改变决策。错误能在地图和日志里直接观察到。

## 项目演示（3 分钟）

1. 第三关（初次启动）：先运行默认的一次前进，说明“语法正确不代表任务完成”；补上另外两次调用并通关。
2. 第七关（直线循环）：使用循环完成多次前进，单步观察同一代码行被重复执行。
3. 第十四关（聪明的选择）：运行条件判断，在日志中观察“前方可通行 / 前方是墙”的两种分支。
4. 切到 Rust：展示 `fn main`、snake_case 函数命名、`0..n` 与显式整数类型。
5. 进入“改造实验室”：更改真实网页的名称、主题和信号灯，通关观察机器人庆祝，点击下一关演示环境自动复位。

遇到临场输入错误，可以使用第三条提示后的参考答案，现场仍然能完整展示运行效果。

## 两种语言如何配合（1—2 分钟）

JavaScript 处理浏览器交互、图形与教学代码解释；Rust 负责规则计算，提前编译成 WebAssembly，在浏览器里直接执行。可指出右上角“Rust 引擎在线”，并展示 Rust 源码中的移动、碰撞与胜利条件函数。

这里使用 WebAssembly 的理由是展示两种语言之间的明确调用边界。地图规模很小，因此本项目没有声称或测得任何性能提升。

## 设计过程与验证（1 分钟）

展示 `design/interface-concept.png`，再回到真实游戏，对照课程导航、编辑器、运行日志和等距实验场。界面由代码实现，地图与机器人会随着代码运行实际变化。

展示 12 份双语解法通关、运行暂停与重置、进度存储等验证内容。解释输入受到指令数与语法限制，任意用户代码不会在浏览器或服务器中执行。

## 边界与后续（约 30 秒）

当前支持六个主题和明确的教学语法；还不能练习 Rust 所有权、借用或完整 JavaScript 标准库。后续可以在完成现有学习目标后增加相应课程，或者引入具有隔离环境的完整编译服务。
